# Security Policy

We take the security of Gru seriously and appreciate the efforts of security researchers who responsibly disclose vulnerabilities.

## Supported Versions

Security updates and critical fixes apply to the latest published release.

| Version | Supported |
|---------|-----------|
| [v0.7.x](https://github.com/ledocorp/GRU/releases) | Yes |
| Older | No |

We recommend always using the most recent release.

## Reporting a Vulnerability

If you discover a security vulnerability in Gru, please report it responsibly.

**How to Report**  
Report security vulnerabilities privately using the contact method listed on the [LedoCorp](https://ledocorp.org) site, or through a private security advisory on GitHub when available. Do not open a public issue for security vulnerabilities.

**What to Include**  
When reporting, provide as much detail as possible, including:

- A description of the vulnerability
- Steps to reproduce the issue
- Potential impact
- Any suggested fixes (if known)

**Response Expectations**

- We will acknowledge receipt of your report within 48 hours.
- We will investigate and provide an initial assessment within 7 days.
- We aim to address confirmed vulnerabilities as quickly as possible, depending on severity.
- You will be credited for the discovery unless you prefer to remain anonymous.

## Scope

This policy applies to the core Gru library and officially maintained components in this repository (`ui/`, `cmd/gru`, sample apps, and public docs).

Third-party dependencies, such as Raylib and WebView2 runtime components, should be reported to their respective maintainers where appropriate. See [docs/licensing/THIRD_PARTY.md](docs/licensing/THIRD_PARTY.md).

## Our Commitment

We are committed to working with security researchers to understand and resolve issues responsibly and in a timely manner. We appreciate your help in keeping Gru secure.
