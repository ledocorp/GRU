# Security Policy

We take the security of Gru seriously and appreciate the efforts of security researchers who responsibly disclose vulnerabilities.

## Supported Versions

Gru follows a rolling release model. Security updates and critical fixes are applied to the latest version.

| Version | Supported |
|---------|-----------|
| Latest | Yes |
| Older | No |

We recommend always using the most recent release to ensure you have the latest security updates.

## Reporting a Vulnerability

If you discover a security vulnerability in Gru, please report it responsibly.

**How to Report**  
Report security vulnerabilities privately using the contact method listed on the project website, or through a private security advisory on GitHub when available. Do not open a public issue for security vulnerabilities.

**What to Include**  
When reporting, provide as much detail as possible, including:

- A description of the vulnerability
- Steps to reproduce the issue
- Potential impact
- Any suggested fixes (if known)

**Response Expectations**

- We will acknowledge receipt of your report within 48 hours.
- We will investigate and provide an initial assessment within 7 days.
- We aim to address confirmed vulnerabilities as quickly as possible, depending on severity.
- You will be credited for the discovery unless you prefer to remain anonymous.

## Scope

This policy applies to the core Gru library and officially maintained components in this repository (including Gru Notes when distributed as part of Gru).

Third-party dependencies, such as Raylib and WebView2 runtime components, should be reported to their respective maintainers where appropriate. See [THIRD_PARTY.md](THIRD_PARTY.md).

## Our Commitment

We are committed to working with security researchers to understand and resolve issues responsibly and in a timely manner. We appreciate your help in keeping Gru secure.
